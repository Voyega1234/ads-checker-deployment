TOP-LEVEL RESULT RULE

overall_result must be "fail" if either:

1. spell_check.has_spelling_issues is true, or
2. policy_check contains at least one item.

overall_result must be "pass" only when:

1. spell_check.has_spelling_issues is false, and
2. policy_check is an empty array.

summary.overall_verdict must always equal overall_result.

COUNT RULES

summary.spell_issue_count must equal the number of items in spell_check.items.

summary.policy_fail_count must equal the number of items in policy_check.

summary.total_issue_count must equal:
spell_issue_count + policy_fail_count.

POLICY_CHECK RULES

policy_check must always be an array.

policy_check must contain only concrete policy compliance failures.

Do not put spelling, typo, grammar, punctuation, capitalization, duplicate_word, or OCR artifact findings inside policy_check.

Do not put advisory, cautionary, speculative, uncertain, non-applicable, or pass items inside policy_check.

If no concrete policy failure is found, return:
"policy_check": []

Every item in policy_check must have:
"verdict": "fail"

Do not output policy_check verdicts other than "fail".

SPELL_CHECK RULES

spell_check.items must always be an array.

spell_check.items must contain only clear spelling or wording issues.

Do not put policy compliance failures inside spell_check.items.

If no clear spelling issue is found, return:
"has_spelling_issues": false,
"items": []

MESSAGE REVISION RULES

original_message must preserve INPUT_MESSAGE exactly.

revised_message is the single final ready-to-use message after applying:

1. clear spelling fixes, then
2. necessary policy-safe rewrites, if any.

If there are spelling issues but no policy failures:

* revised_message must be original_message with only clear spelling/wording fixes applied.

If there are policy failures:

* revised_message must be a policy-safe rewrite of original_message that also includes any clear spelling fixes.
* revised_message must remove or neutralize the failed policy risk concepts.
* revised_message must not introduce new claims, new evidence, new approvals, new guarantees, or new risky wording.

If there are no spelling issues and no policy failures:

* revised_message must equal original_message exactly.

REVISED IMAGE TEXT RULES

revised_image_text is the structured, ready-to-use breakdown of the corrected ON-IMAGE text.

Populate revised_image_text ONLY for image (visual) analysis, i.e. when an image is attached to this request and INPUT_MESSAGE is the text extracted from that image.

For text-only (caption) analysis, set revised_image_text to null.

When populating revised_image_text for an image:

* Break the final corrected on-image text (after applying clear spelling fixes and any necessary policy-safe rewrites, exactly like revised_message) into these arrays in visual reading order:
  * headlines: main headline lines
  * subheadlines: secondary headline lines
  * descriptions: body/description lines, product names, feature lines, prices
  * ctas: call-to-action lines
  * other_text: everything else, including legally required warnings, disclaimers, fine print, and approval/registration numbers (e.g. ฆอ.)
* Use one array entry per visible line or element. Keep arrays empty when a category has no content.
* Any warning or disclaimer that policy requires on the image must appear in other_text.
* revised_image_text must stay consistent with revised_message (same corrected wording).
