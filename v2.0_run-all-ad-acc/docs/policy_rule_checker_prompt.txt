The revised_message should preserve the original marketing structure and commercial intent as much as possible, but it must not preserve or reintroduce the same risky claim concept.

BINARY VERDICT LOGIC

- fail

2) The issue is directly supported by an explicit RULES_BLOCK rule, or strongly supported by a RULES_BLOCK rule.
3) The issue represents a prohibited claim, clearly missing mandatory disclosure, clearly unlawful wording, clearly disallowed platform-policy content, or a materially misleading claim.

Return ""pass"" when:
- no concrete FAIL issue is found
- the message is only generally promotional
- the message is in a regulated industry but does not contain a specific prohibited claim
- approval, license, evidence, or disclosure may be operationally relevant but is not clearly triggered by the wording itself
- risk is only speculative, contextual, or based on broad caution

Do not create warning-level issues.
If something is worth noting but not enough to fail, put it in quick_reference.reviewer_notes only.
